# План разработки кода VANTAGE

Обновлено 11 ноября 2026 года. Цель проекта — мобильный веб-прототип каршеринга в Иркутске для учебной практики и курсовой работы. Согласованные правила описаны в [решениях по продукту](product-decisions.md). Визуальный ориентир — [интерактивный макет](../design/vantage-ui-mockup.html) и [снимок главного экрана](../design/vantage-ui-approved.png).

Работаем по этапам в локальном репозитории. Владелец проекта решает, когда коммитить и отправлять изменения на GitHub. Новые согласованные правила записываем в документ решений по продукту.

## 1. Подготовить проект

**Выполнено.** Клиент и API собраны в npm workspaces. Compose запускает приложение и PostgreSQL, сервер применяет миграции и отдает клиент и API через один порт. Команды запуска и проверки описаны в [README](../README.md#локальный-запуск).

- Создать структуру клиентского приложения, серверного API и базы данных.
- Настроить React и TypeScript на клиенте, Node.js и TypeScript на сервере, PostgreSQL и Docker Compose для локального запуска.
- Добавить пример конфигурации без секретов, инструкцию запуска, начальную миграцию и несколько тестовых автомобилей.

**Готово, когда** по инструкции запускается проект, открывается стартовая страница, а сервер подключается к базе с загруженными тестовыми автомобилями.

## 2. Собрать интерфейс и навигацию

**Выполнено.** Собраны заставка, регистрация, карта и карточки, бронь, поездка, выбор места завершения, условная оплата и итог. Клиент хранит состояние сценария в браузере. Проверка интерфейса описана в [отчете](../design-qa.md).

- Применить навык $frontend-design. Перед реализацией определить палитру, типографику, компоновку и принципы анимации, сверив их с утвержденным макетом.
- Собрать главный экран по согласованному макету. Подготовить заставку с логотипом, регистрацию, бронь, активную поездку, выбор точки завершения, условную оплату и итог поездки.
- Реализовать переходы и состояния загрузки. Использовать строгий премиальный стиль VANTAGE, выразительную типографику и сдержанную анимацию.

**Готово, когда** основной сценарий можно пройти в интерфейсе на тестовых данных.

## 3. Добавить пользователя и автомобили

**Выполнено.** Имя и сессия сохраняются в PostgreSQL. Клиент восстанавливает вход по cookie, загружает каталог из API и показывает доступность, характеристики и фотографии. Проверены повторный вход, недоступный автомобиль, пустой каталог и восстановление после ошибки загрузки.

- Реализовать регистрацию по имени и сохранение демонстрационной сессии в браузере. После заставки новый пользователь видит регистрацию, а уже зарегистрированный попадает на карту.
- Получать список автомобилей с сервера. Показывать доступность, характеристики и фото.

**Готово, когда** приложение загружает данные пользователя и автомобилей через API.

## 4. Реализовать карту и бронирование

**Выполнено.** Карта Иркутска использует React Leaflet и тайлы OpenStreetMap. Сервер создает бронь на 20 минут и освобождает машину при отмене или истечении срока. База ограничивает активные брони и поездки по клиенту и по машине. Открытые карты обновляют доступность каждые две секунды. Проверены оба случая одновременного бронирования и исчезновение и возврат метки без обновления страницы.

- Подключить React Leaflet и подложку OpenStreetMap с видимым указанием авторства и заменяемым источником тайлов.
- Показать доступные автомобили на карте Иркутска, карточку выбранной машины и окно с фото.
- Добавить режимы «На срок» с выбором длительности и «По факту». Кнопка «Забронировать» сразу бронирует доступную машину на текущий момент. Карта остается на фоне, а нижняя карточка показывает обратный отсчет 20 бесплатных минут.
- Реализовать ручную отмену и автоматическое истечение брони. Показать пользователю, если машину уже заняли или бронь истекла. На сервере обеспечить, чтобы у клиента одновременно была максимум одна бронь или аренда, а у машины — максимум один клиент.

**Готово, когда** пользователь может выбрать машину, забронировать ее и отменить бронь. При отмене или истечении брони автомобиль снова доступен. Проверяем два случая одновременного бронирования: два клиента запрашивают одну машину и один клиент запрашивает две машины. В каждом случае проходит только один запрос.

## 5. Реализовать аренду и расчет

- Кнопка «Начать поездку» переводит действующую бронь в аренду и сразу запускает платное время. Во время поездки показывать отдельный экран с данными аренды и текущей суммой.
- Для режима «На срок» показывать оставшееся время и стоимость выбранного периода. При досрочном завершении сохранять цену всего периода. Время сверх срока считать по обычному тарифу.
- Для режима «По факту» показывать прошедшее время и стоимость по фактической длительности.
- Кнопкой «Завершить поездку» открывать карту зоны. Кнопка «Завершить здесь» завершает аренду в допустимой точке и обновляет координаты автомобиля.

**Готово, когда** поездка начинается из действующей брони. Сервер принимает завершение в точке внутри зоны, обновляет координаты автомобиля и рассчитывает итоговую стоимость по обоим режимам. Точку за пределами зоны сервер отклоняет, поездка продолжается.

## 6. Добавить условную оплату и итог

- Показать итоговую сумму после завершения аренды. Кнопка «Оплатить» переводит аренду в статус «оплачена».
- Показать отдельный экран с автомобилем, тарифом, длительностью, суммой и кнопкой «На карту».

**Готово, когда** весь путь от заставки до итога поездки работает с данными сервера.

## 7. Подготовить демонстрацию

- Добавить настраиваемое ускорение времени и сброс тестовых данных.
- Подготовить сценарии обычной аренды, истечения брони, досрочного завершения и превышения срока.
- Проверить интерфейс на телефоне и компьютере, ошибки и восстановление состояния после обновления страницы.

**Готово, когда** сценарии можно повторить по инструкции без ручного редактирования базы или кода.

## Решения перед зависимыми этапами

- Список сроков выбрать до реализации режима «На срок».
- Цены определить до реализации расчета стоимости.
- Границы зоны в Иркутске выбрать до реализации завершения аренды.
- Коэффициент ускорения определить при подготовке демонстрации.

## После разработки. Развертывание и учебные материалы

- Развернуть MVP в подходящей инфраструктуре, проверить полный сценарий и подготовить инструкцию запуска и демонстрации. Место размещения выбрать перед развертыванием.
- По [листу задания](course-assignment-summary.md) описать предметную область, функциональные и нефункциональные требования и ограничения. Сравнить архитектурные стили и обосновать выбор архитектуры и технологий. Описать применимые паттерны проектирования и подготовить ER, UML, DFD и схему развертывания по реализованному проекту.
- Для отчета по практике описать реализованные функции, ход разработки и результаты проверки.
