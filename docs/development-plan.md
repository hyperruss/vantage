# План разработки VANTAGE

Рабочий план, обновленный 11 октября 2026 года. Цель — мобильный веб прототип каршеринга легковых автомобилей в Иркутске. Один кодовый проект будет основой для учебной практики и курсовой работы. Согласованные правила находятся в `product-decisions.md`, визуальный ориентир — `../design/vantage-ui-mockup.html` и `../design/vantage-ui-approved.png`.

## Принцип работы

Разрабатываем приложение небольшими работающими сценариями. После каждого сценария проверяем его на телефоне и в браузере компьютера. Решения, принятые во время разработки, записываем в файл решений. Архитектурные диаграммы и тексты курсовой оформляем по фактически работающему проекту, не откладывая исправление расхождений между кодом и схемами на конец.

## Этап 1. Завершить пользовательский сценарий и дизайн

**Что делаем:** по стилю согласованного главного экрана намечаем экраны простой регистрации по имени, ожидания после бронирования с 20-минутным таймером, активной аренды, выбора точки завершения, итоговой суммы и имитации оплаты. Описываем переходы и состояния ошибок: машина уже занята, бронь истекла, точка вне зоны.

**Результат:** набор компактных макетов и схема переходов. На этом этапе фиксируем элементы интерфейса, от которых зависит реализация, а не прорабатываем каждую декоративную деталь.

**Готово, когда:** по макетам можно пройти путь от выбора автомобиля до оплаты без неясных шагов.

## Этап 2. Подготовить кодовый проект для VS Code

**Что делаем:** в существующем репозитории VANTAGE создаем папки для мобильного веб интерфейса, серверного API, схемы БД и тестов. Материалы проекта уже сохранены в репозитории. Добавляем запуск приложения и БД через Docker Compose, миграции, тестовые автомобили и понятную инструкцию запуска.

**Предлагаемый стек:** React + TypeScript для интерфейса; Node.js + TypeScript для сервера; PostgreSQL для данных; React Leaflet + OpenStreetMap для карты; Docker Compose для локального запуска. Точные серверные библиотеки и инструменты миграций выбираем при создании проекта и фиксируем в репозитории.

**Готово, когда:** новый разработчик может открыть папку в VS Code, выполнить инструкцию и увидеть интерфейс, сервер и тестовые данные.

## Этап 3. Первый сквозной сценарий — выбор автомобиля и бронь

**Что делаем:** реализуем регистрацию по имени и сохранение пользователя, автомобили в БД, показ доступных машин на карте, карточку автомобиля по согласованному макету и окно фото. Клиент выбирает «На срок» или «По факту»; для первого режима выбирает готовую длительность. Бронь действует 20 минут, может быть отменена вручную и автоматически истекает. Один пользователь не может одновременно бронировать или арендовать два автомобиля; одна машина не может быть занята двумя клиентами.

**Готово, когда:** два браузера не могут одновременно успешно забронировать одну машину, а отмененная или истекшая бронь возвращает машину на карту как доступную.

## Этап 4. Аренда, завершение и имитация оплаты

**Что делаем:** добавляем начало аренды из действующей брони, экран активной поездки, завершение в выбранной клиентом точке внутри зоны, перенос координат автомобиля, расчет стоимости и кнопку имитации оплаты. Для аренды на срок оплачивается весь выбранный период; превышение тарифицируется по обычной ставке. Для режима «По факту» считаем фактическое время. Реальные платежи и GPS не подключаем.

**Готово, когда:** клиент проходит путь «бронь → поездка → завершение → сумма → оплачено», а попытка завершить аренду за пределами зоны отклоняется.

## Этап 5. Демонстрационный режим и проверка

**Что делаем:** добавляем настраиваемое ускорение времени, чтобы показывать несколько условных часов за секунды, и отдельный сброс тестовых данных. Проверяем границы тарифов, досрочное завершение, превышение срока, истечение брони, параллельные запросы и восстановление интерфейса после обновления страницы. Проверяем экраны на типичной ширине телефона.

**Готово, когда:** все основные сценарии воспроизводятся по короткой инструкции без ручного редактирования базы или кода.

## Этап 6. Развертывание и учебные материалы

**Что делаем:** готовим стабильную демонстрационную сборку и инструкцию запуска. Для курсовой на основе кода оформляем описание предметной области, требования, ограничения, сравнение архитектур, обоснование стека, ER, UML, DFD и схему развертывания. Для практики описываем реализованные функции, порядок разработки и результаты проверки. Сверяем оба отчета с методическими требованиями, когда они появятся.

**Готово, когда:** приложение запускается по инструкции, демонстрация проходит от начала до конца, а диаграммы и отчеты соответствуют реальной реализации.

## Решения, которые примем в нужный момент

- Границы зоны обслуживания в Иркутске — до реализации завершения аренды.
- Числа для тарифов и список доступных сроков — до реализации расчета стоимости.
- Точная длительность демонстрационной «часовой» единицы — до настройки демонстрационного режима.
- Место размещения демонстрационной версии, если понадобится публичная ссылка — перед развертыванием.

## Порядок ближайшей работы

1. Нарисовать недостающие экраны в стиле VANTAGE и согласовать сквозной путь клиента.
2. В существующем репозитории запустить техническую основу приложения.
3. Реализовать первый сквозной сценарий выбора и бронирования автомобиля.
